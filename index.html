research interests

I want to study how agentic systems verify their own work. Current coding agents generate plausible patches but often can't tell whether a patch is actually correct or only looks correct. I think choosing the correct solution is harder than generating candidates, and it has received less attention.

Production software solves this with scaffolding — tests, review, staged rollout — built precisely because a competent engineer's confidence in their own work is not reliable evidence that it works. Agents largely lack that scaffolding. I'd like to understand what it would take to give it to them, and where self-verification breaks down.

directions I'd like to work on

  • Self-verification and critique — when does an agent's own evaluation of its work correlate with correctness, and when does it fail?
  • Tool use and environment feedback — how much does the ability to execute code, read failures, and iterate change outcomes versus one-shot generation?
  • Evaluation beyond Python — most agentic coding benchmarks target small Python repositories. Enterprise codebases differ in ways that likely matter: heavy dependency injection, framework-driven control flow, long build cycles.
  • Planning under cost constraints — how agents allocate a limited budget of steps, tool calls, and compute across a task.
